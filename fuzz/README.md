# Bounded fuzzing

Install the cargo-fuzz version and nightly in [contributor-tools.toml](../tools/contributor-tools.toml), with nightly `rust-src`. Use a fresh install root outside the checkout:

```sh
python3 -m tools.htmlcut_maintenance install cargo-fuzz --root /outside/checkout/cargo-fuzz
python3 -m tools.htmlcut_maintenance qa fuzz
python3 -m tools.htmlcut_maintenance qa fuzz --runs 250 --require-mutations /outside/checkout/fuzz-results
```

Add the install root's `bin` to PATH. The command builds both targets discovered from this manifest, prepares exact independent corpus inputs, then runs each harness sequentially through the shared bounded process owner. It checks complete iteration counts and post-initialization mutation progress for full smoke and explicitly requested short runs. Reports distinguish initialization from subsequent executions: `--runs` counts both. The default full smoke is 10,000 runs per target; short runs state their scope.

Inputs are at most 64 KiB, including `extract`'s mode byte, little-endian two-byte contract length, contract bytes and document bytes. This accommodates the literal stress cases. Bit 0 selects admission mode: one parse with a node allowance of `(mode >> 2) % 33`, including zero, without requiring a valid contract. Otherwise the harness compiles then parses once, extracts, outlines and checks complete export/render admission. Bit 1 selects a small reading allowance; other semantic inputs permit 64 KiB readings. Fuzz iterations use no cooperative wall-clock cutoff, so instrumentation/load cannot silently skip later operations; the external limits below remain active.

Conformance pairs start in semantic mode; an additional mode-2 copy explicitly exercises the small-reading semantic policy during initialization. Outline source pages use the default `:scope` contract in even semantic mode, so outline invariants run after parsing; equal page bytes under a different contract or mode remain separate inputs. Standalone document seeds start in admission mode across the small node allowances. Authored contract/document bytes remain exact. Generated duplicate inputs share a corpus file only when their complete framed bytes match; `seeds.json` records the input digest, byte length and all qualified `contract/`, `document/` and `outline/` source aliases. Content-derived filenames avoid basename collisions. Each target’s actual unique generated inputs, including the extra mode-2 input, must fit the bounded initial corpus. Different mode bytes remain distinct inputs. A separate bounded admission budget covers the total contract/document/outline source entries (including ignored document directories) before fingerprinting or building, even when complete generated frames deduplicate. Symlink/reparse redirects and nonordinary source files or workspace-owned root/group/case directories refuse before seed reads and fingerprinting; oversized sources also refuse before building. Excessive generated or empty contract discovery refuses. Fuzzing exercises invariants; it does not replay fixture options, outline settings or literal expected answers.

`contract_bytes` probes closed contract admission. Internal failures are findings rather than normal refusals at compilation, preparation, extraction and outline boundaries. Successful extraction values must export canonical JSON under the same bound; raw exports must fit or return a representation refusal. Admitted outlines must render under their allowance. These checks do not require malformed/count/shape/admission refusals to succeed. Small deterministic core property tests separately check expected scalar lists, Unicode/escaping and exact/one-below complete-output limits without a property-testing dependency.

Owned build roots are outside the checkout. Build allowance is 1 GiB sampled disk, 600 seconds and a 4 MiB log; each target permits 64 MiB sampled output, 180 seconds and a 4 MiB log. LibFuzzer also has ten-second per-input and 2 GiB RSS limits. Sampling is not a filesystem quota. Existing Cargo/rustup state is outside those transient allowances and is never pruned. Confirmed successful default runs remove temporary output; explicit output roots and failures retain evidence in a new child directory. Unconfirmed cleanup retains affected products and fails.

`run.json` records completion/status and short/full scope, the source/lock fingerprint, Git dirty or standalone state, input framing, launched arguments and progress. Source changes during seed copying or build refuse before harness launch; changes during execution refuse completion. Unexpected failures retain incomplete evidence. The pinned cargo-fuzz build command has no `--locked` option, so the runner verifies unchanged source/lock inputs rather than inventing that flag. Retained dirty-source hashes establish identity, not a recoverable source snapshot: replay a crash with its matching source, pinned nightly and harness format. Minimize a finding and add an independent literal regression for the corrected behavior.

See [QA boundaries](../docs/qa-resources.md). A short real integration or mocked runner test is not the full required fuzz or mutation review.
